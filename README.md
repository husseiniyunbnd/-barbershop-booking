# سیستم نوبت‌دهی آنلاین آرایشگاه مردانه

رزرو روز و ساعت → ثبت اطلاعات → تأیید جزئیات → پرداخت بیعانه (۵۰۰٬۰۰۰ تومان) → رسید و کد پیگیری، به‌همراه پنل مدیریت.
بک‌اند Node.js (بدون وابستگی خارجی، بدون `npm install`)، پایگاه داده SQLite، رابط فارسی و راست‌چین.

## وضعیت صادقانه‌ی پروژه
| بخش | وضعیت |
|---|---|
| رزرو، ساعت‌ها، قفل موقت، انقضا، جلوگیری از رزرو تکراری | پیاده‌سازی و با ۳۳ تست خودکار + مرورگر واقعی آزمایش شده |
| درگاه **آزمایشی** (mock) | کار می‌کند؛ همه‌جا صراحتاً «آزمایشی» نوشته می‌شود و در حالت production خاموش است |
| درگاه **زرین‌پال** | کد نوشته و روی سرور شبیه‌ساز محلی تست شده؛ **با درگاه واقعی آزمایش نشده** چون مرچنت‌کد در دسترس نبود. قبل از انتشار حتماً یک پرداخت واقعی کوچک امتحان کنید و نشانی‌ها/کدها را با مستندات رسمی زرین‌پال تطبیق دهید |
| پیامک (کاوه‌نگار) و کد تأیید | کد آماده و **پیش‌فرض غیرفعال**؛ فقط با فیک‌پروایدر تست شده، با سرویس واقعی آزمایش نشده |
| پنل مدیریت | کامل؛ احراز هویت و CSRF سمت سرور |
| فونت وزیرمتن | به‌دلیل نبود اینترنت در محیط ساخت، فایل فونت داخل پروژه نیست (بخش «فونت») |
| بازپرداخت بیعانه | سیستم خودکار بازپرداخت **نمی‌کند**؛ مدیر از پنل درگاه برگشت می‌زند و در پنل ثبت می‌کند. سیاست بازپرداخت را شما تعیین می‌کنید (پیش‌فرض: «در انتظار تعیین») |

## ساختار فایل‌ها
```
server/            بک‌اند (index.js ورودی، app.js مسیرها، booking.js هسته‌ی رزرو، payment/ درگاه‌ها، admin.js پنل)
public/            فایل‌های سایت (index.html، admin.html، css، js، img، fonts)
scripts/create-admin.js   ساخت مدیر
test/              تست‌های خودکار
data/              پایگاه داده (app.db خودکار ساخته می‌شود؛ روی GitHub نروید)
.env.example       نمونه تنظیمات (بدون کلید واقعی)
```

## اجرا روی کامپیوتر خودتان
نیاز: Node.js نسخه ۲۲.۱۳ یا بالاتر.
```bash
cp .env.example .env          # ویندوز: copy .env.example .env
npm run create-admin          # نام کاربری و رمز مدیر (حداقل ۱۰ نویسه)
npm start                     # سایت: http://localhost:3000  پنل: http://localhost:3000/admin
npm test                      # اجرای تست‌ها
```
در حالت پیش‌فرض (`PAYMENT_GATEWAY=mock`) پس از «تأیید و پرداخت» به صفحه‌ی درگاه آزمایشی می‌روید.

## تنظیمات اولیه‌ای که باید انجام دهید (پنل مدیریت)
1. **تنظیمات**: نام آرایشگاه، تلفن، نشانی، لینک اینستاگرام (تا خالی است هیچ لینکی نمایش داده نمی‌شود)، قوانین و **سیاست بازپرداخت بیعانه**.
2. **برنامه کاری**: ساعات پیش‌فرض (۱۰ تا ۱۸، جمعه تعطیل) فقط جایگزین موقت است؛ ساعت واقعی را ذخیره کنید. تعطیلات و مسدودکردن ساعت‌ها همین‌جاست.
3. **خدمات**: قیمت، مدت و بیعانه. تغییر قیمت فقط روی رزروهای جدید اثر دارد.

## اتصال زرین‌پال (واقعی)
1. در پنل زرین‌پال درگاه بسازید و **Merchant ID** (کد ۳۶ نویسه‌ای) بگیرید. دامنه‌ی سایت باید روی درگاه ثبت/تأیید شود.
2. در `.env` (یا متغیرهای محیطی هاست):
```
NODE_ENV=production
BASE_URL=https://دامنه-شما.ir
PAYMENT_GATEWAY=zarinpal
ZARINPAL_MERCHANT_ID=کد-پذیرنده
TRUST_PROXY=true
```
3. مبلغ‌ها در سیستم **تومان** هستند و پیش‌فرض هنگام ارسال به درگاه ×۱۰ (ریال) می‌شوند (`ZARINPAL_CURRENCY=IRR`). اگر مستندات/حساب شما تومان می‌خواهد، `IRT` بگذارید.
4. اگر `production` باشد و درگاه mock یا `BASE_URL` غیر https باشد، سرور عمداً اجرا نمی‌شود.
5. نکته‌ی ایمنی که پیاده شده: نتیجه‌ی پرداخت فقط پس از فراخوانی verify از سرور به درگاه پذیرفته می‌شود؛ `Status=OK` در URL به‌تنهایی هیچ رزروی را قطعی نمی‌کند. مبلغ فقط از دیتابیس سرور خوانده می‌شود.
6. اگر پرداخت انجام شد ولی کاربر به سایت برنگشت، سرور هر ۳۰ ثانیه تراکنش‌های نامشخص را از درگاه استعلام می‌کند (و مدیر هم از پنل دکمه‌ی «استعلام تراکنش» دارد).

## انتشار
**GitHub Pages کافی نیست** (فقط فایل استاتیک؛ بک‌اند، دیتابیس و تأیید پرداخت اجرا نمی‌کند). مراحل:
1. پروژه را روی GitHub بگذارید (`.env` و `data/*.db` در `.gitignore` هستند).
2. روی یک سرویس که Node.js و **دیسک پایدار** دارد مستقر کنید (VPS ایرانی/خارجی، Render، Railway، Fly.io و …):
   - Build: ندارد. Start: `npm start`. نسخه‌ی Node ≥ 22.13.
   - دیسک پایدار را به مسیر `data/` وصل کنید یا `DATABASE_PATH` را به آن بدهید.
   - متغیرهای بالا را در تنظیمات محیطی هاست بگذارید و HTTPS فعال کنید.
   - فقط **یک نمونه (instance)** اجرا کنید (SQLite).
3. یک بار `npm run create-admin` را روی سرور اجرا کنید.
4. توجه: گاهی درگاه‌های ایرانی به IP خارجی پاسخ نمی‌دهند؛ اگر هنگام پرداخت خطای «اتصال به درگاه» دیدید، سرور داخل ایران را در نظر بگیرید.
5. از فایل `data/app.db` به‌طور منظم نسخه‌ی پشتیبان بگیرید.

## فونت
فونت «وزیرمتن» (مجوز OFL) را دانلود کنید و فایل variable را با نام `Vazirmatn.woff2` در `public/fonts/` بگذارید. تا آن زمان فونت سیستم نمایش داده می‌شود. لوگو: فایل را در `public/img/` بگذارید و نشانی آن را در تنظیمات پنل بدهید (پیش‌فرض: `public/img/logo.svg`).

## پیامک
`SMS_ENABLED=true` + `SMS_API_KEY` + `SMS_SENDER` (کاوه‌نگار). پس از فعال‌سازی: پیامک تأیید رزرو، یادآوری (پیش‌فرض ۳ ساعت قبل)، اعلان لغو و در صورت `OTP_REQUIRED=true` کد تأیید شماره. پیش از استفاده یک پیامک آزمایشی واقعی بفرستید.

## امنیت (خلاصه)
اعتبارسنجی سمت سرور، کوئری‌های پارامتری، نشست مدیر با کوکی HttpOnly/SameSite=Strict، توکن CSRF، قفل ورود پس از ۵ تلاش، رمز با scrypt، محدودسازی نرخ، CSP و هدرهای امنیتی، رسید فقط با توکن امضاشده، عدم نمایش جزئیات خطا، خروجی CSV ایمن در برابر تزریق فرمول.

## قواعد رزرو (قابل تنظیم)
مهلت پرداخت ۱۵ دقیقه؛ رزرو تا ۲۱ روز آینده؛ حداقل ۶۰ دقیقه فاصله تا نوبت؛ حداکثر ۲ رزرو پرداخت‌نشده برای هر شماره. اگر پرداخت دیرتر از مهلت برسد و ساعت هنوز آزاد باشد نوبت قطعی می‌شود؛ اگر ساعت به نفر دیگری رسیده باشد رزرو با برچسب «نیازمند بازپرداخت» در پنل می‌آید.
